# 乐谱时值与延音契约

谱面编辑者输入 measures（1..200，按时间排列）、events（0..2000）与 transpose（-127..127半音）。measure 有唯一id、numerator 1..32、denominator 取1/2/4/8/16/32/64，小节长度以四分音符为1，精确等于 numerator*4/denominator。

event：全局唯一id、voice id、measure id、start、duration、pitches，可选tie_to。时间用非负分子/正分母整数对，分子<=100000、分母<=10000，duration必须正；start为小节内偏移。pitches 为排序唯一0..127 MIDI数组（最多16），空数组是休止。移调后越界拒绝。

每个出现过的声部均审核全曲全部小节，包括空小节。同一声部多音必须写成单个和弦事件，事件交叠诊断为overlap；gap按区间并集检测，超出所属小节输出overrun，诊断保留输入事件id。无事件的谱面没有可推断声部，不产生gap。

未知tie目标、多条入边作为结构错误拒绝；合法tie须同声部、同非空和弦、且目标全曲绝对起点等于来源终点。非法tie输出诊断并拆开；合法链只合并发音跨度并保留全链id。合法链严格向时间前进，不成环。诊断不阻止生成跨度；有overrun的事件仍按声明绝对坐标输出，不宣称谱面通过。成功CLI退出0代表报告已生成，合规性需读diagnostics。

不含音频、踏板、节拍器速度、重音、反复段、异名同音或调号拼写。后续分谱、反复展开可接入measure/event/voice身份与原有时间审计。输出只创建不覆盖，输入未知字段/重复键等拒绝，失败返回2。样例为自制。

## 演奏顺序窗口：process_window

`score_spans.service.process_window(score, sections, first, stop)` 在不改动旧入口的前提下提供反复编排查询，可直接从 Python 调用，返回可 JSON 序列化对象，不生成或播放音频。它与 `process` 使用两条不同时间轴：

* `process`（含 CLI）使用**源谱时间轴**：小节按 `measures` 数组顺序排列，`tie_to` 按源谱绝对坐标兑现，失败产生源序 `invalid_tie`。
* `process_window` 使用**演奏时间轴**：按 `sections` 反复后的实际出现排列，每次出现有从 0 开始的 `ordinal`，全曲起点按实际经过的小节长度（四分音符为 1 的精确分数）累加，事件身份是 `[ordinal, event_id]`。源谱上 `tie_to` 指向更早小节不再被视为输入错误；是否兑现只按演奏顺序判定。

`sections` 为 1..100 项，每项恰有 `from_measure`、`through_measure`、`repeat`：取源谱中两个小节 ID 之间（含两端）的连续小节，依序连续出现 `repeat`（1..1000000000）次后再接下一段；段可重叠、重复使用或重排。查询窗口为半开 ordinal 区间 `[first, stop)`，必须落在编排范围内且覆盖 1..8 个小节；边界须为整数（布尔值拒绝）。非法谱面、段形状、小节引用、倒置段、次数或窗口均抛 `ValueError`，不返回部分结果。

### 演奏顺序下的延音规则

事件只有非休止且不越出所属小节时才有资格发音或参与延音；重叠不取消发音，也不隐式合同和弦。每条 `tie_to` 只绑定一个实际目标：

* 来源终点严格在小节内：只尝试同一次小节出现中的目标，目标须同声部、移调后完整非空和弦相同、不越界，且全曲起点精确等于来源终点。
* 来源终点恰为小节末尾：只尝试紧接着的下一次小节出现（可来自同段下一轮或下一段），目标起点须为小节零点。没有下一小节即失败。
* 找不到合格目标（来源休止/越界同样）即断链；不越过休止、未命中段或中间小节，不回溯已经过的小节。同一源声明在不同实际出现中可以一次成立、另一次失败。

发音跨度按整份编排中的完整合法延音链定义，单个未相连音符也成链。窗口只裁剪可见区间与可见成员，不重新决定链的起止。

### 输出

对象含 `measures`、`spans`、`diagnostics` 三个数组，时间一律为规范精确字符串（整数如 `"4"`，否则约分 `"n/d"`）：

* `measures`：窗口内每次出现的 `ordinal`、源 `measure`、全曲 `start` 与 `length`。
* `spans`：每条与窗口有正长度交集（相切不计）的链，含 `voice`、移调后 `pitches`、裁剪的 `start/end`、未裁剪的 `full_start/full_end`、首尾实际身份 `first_event/last_event`、整链 `member_count` 与按时间排列的 `visible_events`，按 `(start 数值, voice, first_event ordinal, first_event event_id)` 排序。
* `diagnostics`：对源谱出现过的每个声部审核窗口内每次小节出现（含该声部无事件的小节），`gap/overlap/overrun` 沿用原字段与小节内坐标并加 `ordinal`；越界事件仍参加覆盖审核但不发音。另为窗口内每个未兑现延音来源输出 `{kind:"invalid_tie", ordinal, from, to}`，检查下一小节时不受窗口右边界影响；窗口外来源不报告。调换源 `events` 数组顺序不改变输出。

编排与链均压缩存储：不展开重复轮次、不输出完整链成员，跨轮次链的端点与成员数由段槽位函数图按算术跳跃得到，重复次数达到 10^9 时查询仍为毫秒级、内存与重复次数无关。
