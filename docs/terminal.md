# 排练终端断点续送契约：open_transfer / TerminalDelivery

`score_spans.terminal` 在旧谱面处理、演奏窗、语料发布、对账入口与 CLI 之外，
提供一套纯 Python、只依赖标准库的本地数据接口，把一份谱转换成外接琴键
提示终端能消费的"输出通道、音高、开关"指令，并依据终端回执断点续送。
本模块只做结构化数据：不驱动硬件、不接网络、不做播放器或 CLI。

```python
from score_spans.terminal import open_transfer, TerminalDelivery

delivery = open_transfer(
    'transfer-7',          # 唯一传送标识，走现有 ID 规则
    0,                     # 初始终端代号（非负整数）
    score,                 # 现有源谱（measures/events/transpose）
    {'v1': 1, 'v2': 1},    # 声部 -> 1..16 通道，同一通道可多声部共用
    2)                     # 每包操作上限 K，1..64
packet = delivery.next_packet()        # 保存检查点后才真正发送
delivery.receive_receipt(              # 回执先应用到检查点再取下一包
    packet['transfer_id'], packet['terminal_code'], packet['packet_index'])
delivery.record_reset(1)               # 终端通知复位到更大的代号
delivery.confirmed_position()          # 最后确认的整帧奏谱位置
blob = delivery.to_json()              # 调用方自行保存最新检查点
delivery = TerminalDelivery.from_json(blob)
```

调用方串行操作，本模块不管理文件、不处理并发。

## 开传输入与沿用规则

`open_transfer(transfer_id, terminal_code, score, channels, k)`：

* `transfer_id` 走现有 ID 规则（`[A-Za-z0-9_:-]{1,64}`）；`terminal_code`
  是非负整数（布尔值拒绝）；`k` 是 1..64 的整数。
* `channels` 是声部 ID 到 1..16 整数通道的对象。每个**非休止声部**必须有
  映射；可为仅有休止的声部给映射；引用谱外声部（连休止事件都不存在）
  拒绝。空事件表没有声部，空映射合法。
* 传送开始后标识、代号、谱、映射与 K 均不变；谱按源顺序只读一次。沿用
  现有精确时值、移调（移调后音高须在 0..127）与合法延音合并规则。
* 谱面校验与对账入口同口径：同声部重叠（`overlap`）、越界（`overrun`）
  或无效延音（`invalid_tie`）拒绝开传；留白（`gap`）、纯休止或空事件
  表允许，此时没有任何指令帧，首次取包即返回 `None`。

## 从谱面到指令帧

合法延音合并后的每条发音链在半开区间 `[start, end)` 内，对每个和弦音
占用一个物理键 `(channel, transposed_pitch)`。休止不产生占用。帧编译
规则：

* 同一时刻统一处理所有开始与结束。一个物理键在**首次占用**时开，在
  **最后一个占用结束**时关；只要还有一条占用越过此时刻，键保持打开。
* 旧占用在此刻全部结束而新占用同时开始时，即使键号没变也**先关后开**，
  以体现新起音；合法延音链是整条区间占用，链内接缝不重触发。
* 同刻所有关操作排在所有开操作之前；两组各自按 `(通道, 音高)` 升序。
* 没有操作的时刻不产生帧；帧时间一律是规范精确分数字符串（整数如
  `"4"`，否则约分如 `"1/3"`）。只用谱面时间，实际发送时机由调用方负责。

例：同通道上 A60`[0,2)`、B60`[1,3)`、C60`[3,4)`、D64`[3,4)`、E67`[3,4)`
只产生三帧——0 时开 60；3 时严格为关 60、开 60、开 64、开 67（1、2 时
无帧）；4 时关闭这三个键。同音高但不同通道是不同物理键，互不影响。

## 包协议

每个非空指令帧按帧内操作顺序切成每包至多 `k` 个操作，前面的包装满。
包是普通 JSON 对象，字段固定：

| 字段 | 含义 |
| --- | --- |
| `transfer_id` | 传送标识 |
| `terminal_code` | 发出该包时的终端代号 |
| `packet_index` | **代号内**从 1 开始的包序号，复位后归 1 |
| `frame_kind` | `score`（奏谱）或 `recovery`（恢复） |
| `time` | 谱面时间字符串；恢复帧为所恢复的确认位置，初始位置可为 `null` |
| `fragment_index` | 帧内片号，从 1 开始 |
| `fragment_total` | 该帧总片数 |
| `operations` | 本片操作，每项恰为 `{channel, pitch, switch}`，`switch` 为 `on`/`off` |

终端按 `(transfer_id, terminal_code, packet_index)` 去重，只接受自己当前
代号，收齐同一帧的全部片才按顺序一起执行。每个非末片的回执只表示该片
已暂存；末片回执表示整帧已执行。回执字段为 `{transfer_id,
terminal_code, packet_index}`，既可按三个位置参数传入，也可传单个字典。

## 取包、回执与检查点时机

调用方严格串行，推荐循环如下：

1. `next_packet()` 取出一个完整包（或得到 `None` 表示结束）；
2. **先保存最新 JSON 检查点，再把包发给终端**；
3. 收到回执后先 `receive_receipt(...)` 应用到状态并保存检查点，再回到
   第 1 步取下一包。

状态机保证：

* 未收到回执前反复 `next_packet()`（包括从检查点重新载入后）返回同一
  个完整包，包序号与内容字节级一致。
* 非末片回执只把该片标记为暂存，之后才可取同帧下一片；不推进奏谱位置。
* 末片回执才推进：奏谱帧把最后确认位置推进到该帧时间；恢复帧不推进
  谱面位置。
* 无更多包时 `next_packet()` 明确返回 `None`。
* 当前代号中已确认包的重复回执幂等无副作用；未发出的包（序号超前）、
  错误传送标识、非当前代号（旧代号或尚未获知的未来代号）一律抛
  `ReceiptRejected` 且无副作用。没有在途包时任何回执都拒绝。

## 复位与恢复

终端通知复位到**更大**的代号时，终端已清空所有物理键与暂存片：

* 保留最后确认的**整帧**奏谱位置；丢弃旧代号的待发包与该未确认整帧的
  分片进度；包序号在新代号重新从 1 开始。
* 旧代号回执此后不起作用；重复或更旧的复位通知幂等忽略，不回退。
* 新代号先交付一个**恢复帧**：把最后确认位置执行完毕时应亮的物理键每
  键开一次，顺序按 `(通道, 音高)` 升序；该位置没有亮键时跳过恢复帧。
  初始位置（尚无任何整帧确认）没有键，同样跳过。
* 恢复帧同样受分包与逐片确认约束，不推进谱面位置；恢复途中再次复位，
  仍从同一确认位置的恢复首片重来。恢复完成前不会混入任何奏谱包。
* 恢复完成后从下一奏谱帧的**首片**开始交付，即便该帧此前曾发到末片但
  回执丢失。恢复不能靠重发已确认的历史奏谱帧实现——那会制造过去的
  起音；恢复帧只含开键、不含关操作。

## 检查点格式

`to_json()` / `from_json()` 使用标准 JSON（`sort_keys`、拒绝非有限值）。
检查点只保存恢复交付所必需的最新状态：

```text
format          固定 "score-spans.terminal/1"
transfer_id     传送标识
terminal_code   当前终端代号
packet_limit    每包操作上限 K
score           源谱（一份，传送期不变）
channels        声部到通道映射
confirmed_until 最后确认整帧在帧数组中的下标，-1 表示尚无确认
phase           score 或 recovery
cursor          当前帧游标（完整操作序列、帧下标与下一片号），无帧时 null
packet_counter  代号内下一个可分配包序号，复位后归 1
outstanding     已取出未确认的完整包，无在途包时 null
```

检查点**不累计**已送包序列、过去的代号或历次检查点。`from_json` 会重新
编译帧并核对全部不变量：游标操作必须与按当前谱重算的帧（或确认位置的
应亮键集合）逐字一致、在途包必须是最后发出的那一片且其分片/时间/操作
与游标匹配、计数器与代号落在合法范围。任何破坏抛 `InvalidCheckpoint`。
检查点格式是实现细节，只应通过这两个方法访问。

## 错误类型

均可按异常类型或稳定 `code` 属性区分，基类 `TerminalError`：

| 类型 | code | 含义 |
| --- | --- | --- |
| `InvalidTransfer` | `invalid_transfer` | 开传参数或谱面结构非法（也是 `ValueError`） |
| `ReceiptRejected` | `receipt_rejected` | 回执传送/代号不匹配、包未发出或无在途包 |
| `InvalidCheckpoint` | `invalid_checkpoint` | JSON 检查点形状或不变量被破坏 |

任何被拒绝的回执或复位通知都不改变状态。

## 测试

在本仓根目录（已安装本包或把 `src` 加入 `sys.path`）：

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

`tests/test_terminal.py` 覆盖：

1. 验收帧语义：同通道五声部的开/关/先关后开与排序、无操作时刻无帧、
   精确分数延音链接缝不重触发、同音高不同通道互不影响、跨时刻保持；
2. K=2 分包与恢复屏障：末片未到/末片已生效但回执丢失两种复位情形，
   载入检查点后只恢复确认位置的键、旧末片回执不能越过屏障、恢复后
   完整重送两片且只有末片确认才推进位置，以及无复位对照下原代号
   重取原末片、终端去重不重复执行；
3. 恢复本身分片、恢复途中再复位从首片重来、恢复完成前不混入奏谱包、
   无键恢复跳过；另覆盖空谱、非法输入、非当前传送/未发包/重复回执、
   输入事件重排、检查点损坏检测与本地接收端替身的端到端亮键核对。

## 边界

本模块不改变 `process` / `process_window` / 语料发布 / 对账 / CLI 的任何
行为；不持久化文件、不处理并发、不调度真实时间。调用方负责传送标识的
全局唯一性、检查点文件的保存时机与真实终端的收发。
